# Deploy FoodClub

Two supported paths: **Render** (free tier, recommended for portfolio) or **VPS + Docker Compose**.

---

## Option A — Render (recommended)

### Prerequisites

- Code pushed to GitHub: `https://github.com/vidya252005/Food-Delivery-Application`
- [Render](https://render.com) account (free)

### 1. Create services from Blueprint

1. Open [Render Dashboard](https://dashboard.render.com) → **New** → **Blueprint**
2. Connect GitHub and select **Food-Delivery-Application**
3. Render reads `render.yaml` and creates:
   - **foodclub-db** — PostgreSQL
   - **foodclub-api** — backend (Docker, port 5001)
   - **foodclub-web** — React static site

4. When prompted, set these **manual** env vars (same Google Client ID in both):
   - `foodclub-api` → `GOOGLE_CLIENT_ID`
   - `foodclub-web` → `REACT_APP_GOOGLE_CLIENT_ID`

5. Click **Apply** and wait for deploy (~5–10 min first time)

### 2. Seed demo data (once)

Render **Shell** is not available on the free tier. Use either method below.

#### Method A — seed from your laptop (recommended)

1. Render → **foodclub-db** → **Connections** → copy **External Database URL**  
   (looks like `postgresql://food_delivery_app:PASSWORD@dpg-xxxxx.oregon-postgres.render.com/food_delivery`)

2. On your Mac, from the project folder:

```bash
cd backend
npm ci
DATABASE_URL='postgresql://USER:PASS@HOST/food_delivery' node scripts/seed.js
```

Replace with your full External Database URL from Render (wrap in quotes).

3. Verify:

```bash
curl https://foodclub-api-d79l.onrender.com/api/restaurants
```

#### Method B — one-time seed on deploy (no Shell)

1. **foodclub-api** → **Environment** → add `RUN_SEED` = `true`
2. **Manual Deploy** (pre-deploy runs migrate + seed)
3. Remove `RUN_SEED` or set to `false` after seed succeeds (seed wipes data if run again)

Demo login: `priya@example.com` / `password123`

### 3. Google OAuth (production)

In [Google Cloud Console](https://console.cloud.google.com/apis/credentials) → your OAuth client:

**Authorized JavaScript origins** — add your live frontend URL, e.g.:

- `https://foodclub-web.onrender.com`

**Authorized redirect URIs** — not required for this app’s button flow, but origins must match.

Redeploy **foodclub-web** after changing `REACT_APP_GOOGLE_CLIENT_ID`.

### 4. Verify

```bash
curl https://foodclub-api.onrender.com/health
```

Open `https://foodclub-web.onrender.com` in the browser.

### Notes

- Free web services **sleep after ~15 min idle** — first request may take 30–60s.
- `JWT_SECRET` is auto-generated by Render.
- CI on GitHub still runs tests; Render deploys on Blueprint sync / manual deploy.

## Option B — VPS + Docker Compose

For a small VM (DigitalOcean droplet, AWS EC2, etc.) with Docker installed.

### 1. Environment

Create `/project/.env` at repo root:

```env
JWT_SECRET=your-long-random-secret-here
PG_PASSWORD=strong-db-password
GOOGLE_CLIENT_ID=your-google-client-id
REACT_APP_API_URL=https://your-domain.com/api
CORS_ORIGINS=https://your-domain.com
FRONTEND_URL=https://your-domain.com
```

Generate secret:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

### 2. Build and run

```bash
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml exec backend node scripts/seed.js
```

- Frontend: `http://YOUR_SERVER_IP` (port 80)
- API: `http://YOUR_SERVER_IP:5001`

Put **nginx/Caddy** or a cloud load balancer in front for HTTPS on a real domain.

## Environment checklist

| Variable | Where | Required prod |
|----------|--------|----------------|
| `JWT_SECRET` | Backend | Yes |
| `PG_*` / database | Backend | Yes (auto on Render) |
| `CORS_ORIGINS` | Backend | Yes — your frontend URL |
| `FRONTEND_URL` | Backend | Yes |
| `GOOGLE_CLIENT_ID` | Backend | For Google login |
| `REACT_APP_API_URL` | Frontend build | Yes — `https://api.../api` |
| `REACT_APP_GOOGLE_CLIENT_ID` | Frontend build | For Google login |

Never commit `.env` files with real secrets.

## Troubleshooting

### `Missing script: "dev"` / build runs `yarn` at repo root

Render is treating the repo as a **Node Web Service at the root**, not as the backend in `backend/`.

**Fix on the existing `foodclub-api` service (fastest):**

1. Open **foodclub-api** → **Settings**
2. Set **Root Directory** → `backend`
3. Set **Environment** → **Node** (not Docker unless you know Docker is configured)
4. **Build Command** → `npm ci --omit=dev`
5. **Start Command** → `node src/server.js`  
   (delete `npm run dev` — that is local-only)
6. **Pre-Deploy Command** → `node src/db/migrate.js`
7. **Save** → **Manual Deploy**

Also confirm you have a **PostgreSQL** database linked with `PG_HOST`, `PG_PORT`, `PG_DATABASE`, `PG_USER`, `PG_PASSWORD`, plus `JWT_SECRET` and `GOOGLE_CLIENT_ID`.

**Full stack (recommended):** delete the broken service → **New → Blueprint** → select repo. Render reads `render.yaml` and creates database + API + static frontend.

| Service | Type | Settings |
|---------|------|----------|
| **foodclub-api** | Web Service | Root dir `backend`, Build `npm ci --omit=dev`, Start `node src/server.js`, Pre-deploy `node src/db/migrate.js` |
| **foodclub-web** | **Static Site** | Build: `chmod +x frontend/scripts/render-build.sh && ./frontend/scripts/render-build.sh`, Publish: `frontend/build`, rewrite `/*` → `/index.html` |
| **foodclub-db** | PostgreSQL | Free plan |

### Other issues

| Issue | Fix |
|-------|-----|
| API `JWT_SECRET must be set` | Set `JWT_SECRET` on backend service |
| Frontend shows network errors | Check `REACT_APP_API_URL` points to `/api` on backend URL |
| CORS blocked | Add frontend URL to backend `CORS_ORIGINS` |
| Empty restaurant list | Run `node scripts/seed.js` on backend |
| Google login fails | Add production origin to Google Console |
